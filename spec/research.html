Build a Rust daemon with Orca's detection model and herdr's discipline

Design rule: terminal first. Lotse is a terminal app like iTerm2, with projects and agent awareness like Orca. The main view is the full-size agent CLI (Claude Code, Codex or OpenCode). Changes, files, usage and session details are right-panel views that stay hidden until you open them from icons, as in the Claude Code desktop app: Session ⇧⌘I, Changes ⇧⌘D, Files ⇧⌘F, Transcript ⇧⌘T, Usage ⇧⌘U. Full diff (⌥⌘D) and Settings (⌘,) take over the whole window, with Esc to go back. The reference mock is mocks-v3/00-quick-main.html.

From Orca

Hook-first status detection, a sub-agent roster, the notification model, the UI layout and the pairing crypto. MIT licensed.

From herdr

A Rust server/client split, 0600 Unix sockets, TOML detection manifests, process-group identity and the test discipline. Apache-2.0 licensed.

Stack (approved)

A Rust core daemon with a Tauri 2 shell (React, Tailwind, xterm.js). The same web UI later serves the LAN mobile client.

Security and telemetry: what the code shows

Your claim is partially confirmed. Orca sends telemetry to the US by default, but it does not ship logs.

  • PostHog is hard-coded to the US cloud at us.i.posthog.com (src/main/telemetry/posthog-transport.ts:82). Fresh installs default to optedIn: true (loaded-cohort-migrations.ts:110-115), and no first-run consent step exists in the onboarding code. For existing users, dismissing the banner counts as consent.
  • What it sends: usage events limited by a zod schema (104 events). Each carries the app version, OS, a random install ID and agent token counts. The code excludes prompts, paths and terminal output. Crash dumps are never uploaded, and diagnostic logs are sent only after you preview them and click Send.
  • Opt-out works and is enforced in main. You can turn it off in Settings › Privacy or with DO_NOT_TRACK or ORCA_TELEMETRY_DISABLED. The writer key is injected only into official CI builds, so a build from source sends nothing.
  • Other Orca risks:
    • The WebSocket on :6768 widens to 0.0.0.0 over plain ws:// once a network device has paired. It is E2EE inside.
    • The renderer CSP sets only img-src.
    • The IPC surface is very large (~980 preload calls), and frames are rarely checked for the sender.
    • Computer use has no per-action approval.
    • Secrets fall back to plaintext files under ~/.orca when safeStorage is unavailable.
    • It polls onorca.dev for nudges and changelogs, with no setting to turn that off (likely; I found none).
  • herdr: no telemetry. Its only outbound calls are an update check and a detection-manifest fetch from herdr.dev, both on by default and both can be turned off with [update] version_check/manifest_check = false.
    • Fetching remote regex manifests is a supply-chain trust point.
    • The self-updater shells out to curl; signature checking was not audited.

What to take, what to skip

Take

  • Hook-first detection (Orca). Claude Code hooks provide PermissionRequest, Stop, StopFailure, SubagentStart/Stop and PostToolUseFailure, which give exact states including failed. Hooks POST to a token-guarded endpoint (use a Unix socket rather than TCP).
  • OSC 7501 compatibility (Orca). Agents that emit it, including Codex and Claude, work without installers.
  • Screen-scrape fallback with TOML manifests (herdr). Bundle them and let users override them locally, with no remote fetch.
  • Process-group identity (herdr) to find which agent runs in a pane.
  • Sub-agent roster (Orca). Show child rows, and let child work hold the lead agent "in progress".
  • Turn-outcome model (Orca), which gives you failed as distinct from done.
  • Notification rules (Orca and herdr): per event type, suppress for the focused pane, a 1.5 s quiet window, burst cooldown, sound per event.
  • Daemon plus client (herdr and Orca). PTYs survive UI restarts, use 0600 sockets, and session writes are atomic.
  • Hot-reload TOML config and config check (herdr).
  • The pairing design for later (Orca): a QR carrying a pinned X25519 key, a device key, a per-device grant (read vs approve), and revocation.
  • UI layout (Orca): workspace cards with agent rows, a resizable sidebar, and grouping by status.

Skip

  • Electron: ~200 MB of RAM per window, a Chromium attack surface and the IPC sprawl.
  • Telemetry of any kind. No outbound network by default; make it a selling point.
  • Cloud relay and sign-in. LAN only; use Tailscale or WireGuard to reach it from elsewhere.
  • Jira and Linear integrations, automations, account switching: scope creep. The browser, computer use and a full editor move to post-MVP, and only a light editor stays in the MVP.
  • Remote manifest and auto-update fetches by default (herdr). Offer opt-in Sparkle with EdDSA signatures instead.
  • Plain ws:// on 0.0.0.0 that widens automatically (Orca). Bind only to an explicit interface the user picked, use TLS with a pinned certificate, and keep it off by default.
  • Plaintext secret fallback. Keychain only.
  • TUI and tmux prefix model (herdr). You want a GUI; keyboard shortcuts should follow macOS conventions.
  • Supporting 24 to 35 agents at the start. Do Claude Code, Codex and OpenCode well, and treat the rest as generic.

Sidebar design rules

Reference: mocks-v3/00-quick-main.html. Calm by default; colour and detail appear only where something needs you.

Layout and sizing

  • Resizable 200–420 px, default 260, width persisted. Hide and show with ⌃⌘S. Dragging captures the pointer and blocks text selection.
  • Scrolls vertically, never horizontally. Search and the Projects header stay fixed; only the project list scrolls.
  • Long text truncates with "…" (project, title, branch, sub-agent) and shows the full value on hover. No content may push the sidebar wider or stop a resize.
  • Project row: coloured folder tile (user-picked colour and SF Symbol), name, no-git and muted-notification badges. The disclosure chevron appears only on hover or focus (Finder style).

Status

  • One icon set, 14 px (12 px for sub-agents), shape plus colour so it reads without colour: spinning ring in progress, filled triangle needs permission, filled ✕ circle failed, filled ✓ circle done, outline circle idle. SF Symbols in the native build.
  • Roll-up only when collapsed. An expanded project shows no status (its sessions do). Collapsed: needs-you counts first (▲2, ✕1), else the top state. Idle shows nothing.
  • Project colours never use status hues (no red, orange, green or system blue lookalikes in the default palette).
  • Reduce Motion stops the spinner.

Session card

  • Line 1: status, task title (from the first prompt or the agent's summary, editable), unread dot, time. Never repeat the agent name as the title.
  • Line 2 (dim, 11 px): agent · worktree or branch icon · branch (no lotse/ prefix; full name in tooltip) · ↑ahead · ±dirty. Non-git projects show the agent only.
  • Time is coarse in the sidebar (<1m, 4m, 1h 5m) so it doesn't tick every second; seconds live in the Session panel.
  • Stable under the pointer: the sidebar updates only when its visible text changes, and defers updates while the pointer or keyboard focus is in it, so hover states and buttons never flicker. Status changes patch rows in place in the real build.
  • Sub-agents fold away: listed only for the selected session or when one needs you; otherwise one line, "3 sub-agents · 1 running".
  • Permission actions always visible: Allow (blue, primary) / Always / Deny sit under the title whenever a session needs permission. No hover reveal: it's the moment you need them.
  • Failure action in place: on hover or focus, the time swaps for a ↻ Retry button in the same row, so the card height never changes. Clicking the card opens the session and its log.
  • No layout shift: hover and focus may change colour or swap content inside a row, never add rows or change card height.

Interaction

  • Selection is a soft tint, no border or outline. Keyboard focus shows a blue ring.
  • Keyboard: ↑/↓ moves between sessions, Enter opens, ⌘J jumps to the next one that needs you.
  • "▲ n need you" filter (footer) shows only sessions that need attention, with a Show all chip.
  • Right-click: project menu (New session, Notifications: global / custom / mute, Change icon and colour, Reveal in Finder, Copy path, Rename, Remove) and session menu (Open, Split right, Show transcript, Show changes, Stop).
  • Drag: a session onto the terminal to split; a folder onto the sidebar to add a project. ⌥-click splits.
  • Empty project: "No sessions · New session" instead of a blank row.

Right panel design rules

Hidden by default, 340 px, opened from the toolbar icons. They support the terminal; they never replace it. Reference: mocks-v3/00-quick-main.html.

Shared anatomy

  • Header: title, a dim one-line context (agent · model · start time, or the worktree path), and at most one control on the right (toggle or Export).
  • Search or filter field under the header with its shortcut shown (⌘P files, ⌘F transcript). Filters keep typing focus while results update.
  • Segmented controls for views and filters, each with a count (Changed 3, Tools 4, Approvals 1).
  • Empty states say what happened ("No files match", "No matches") instead of showing a blank panel.
  • Same rules as the sidebar: status icons and colours, truncation with tooltips, and no layout shift on hover.

Files (⇧⌘F)

  • Tree of the session's worktree (or main checkout), not the whole disk. Finder-style chevrons, folder and file-type icons, UI font, 26 px rows.
  • All / Changed toggle. Changed files show +added −removed and an A / M / D badge; a collapsed folder with changes shows a dot.
  • Click any file to open it in an editor pane beside the terminal. Hover swaps the counts for Open in external editor and Copy path.
  • Footer: file count, changed count, and Review changes (full diff).
  • Non-git projects show the tree without the toggle or badges.

Transcript (⇧⌘T)

  • Your prompts as right-aligned bubbles; agent replies as plain text with name and time.
  • Consecutive tool calls grouped into one compact card: icon, tool (sub-agent tasks show as Agent), target in mono, result, status icon. Exact time on hover.
  • Approvals as an orange card: what was allowed or denied, the command, who decided and from where (notification, phone, sidebar).
  • Filters: All / Messages / Tools / Approvals. Export (Markdown, JSON Lines, terminal text), saved locally with secrets redacted.
  • While the agent runs, a bar at the bottom shows what is working and a Latest ↓ jump.

Usage & time (⇧⌘U)

  • Session time first: three tiles, Session (since start), Working (agent active) and Waiting on you (orange), with a split bar under them. This is where session time lives; sidebar cards show coarse time with a tooltip pointing here.
  • Timeline: one lane per agent and sub-agent on a shared time axis (start → now). Segments use status colours (working blue, waiting orange, done green, failed red); each lane shows its duration and cost.
  • Tokens: one stacked bar split into input, cache read and output, with values.
  • Spend today: session, project and all projects, as comparison bars.
  • Costs are local estimates from transcripts and the panel says so. Nothing leaves the Mac.

Editor pane

  • Opens as a split pane right of the agent terminal, from the Files panel or a file path. It shares the split system: resizable divider, ⌘[ / ⌘] focus, ⌘W close, 4 panes max (a new file replaces the last editor when full). The terminal is never replaced.
  • Header: file icon, name, unsaved dot, project/path (so it stays clear next to another project's terminal), Diff toggle for agent-changed files, Expand (⌥⌘↩, Esc restores) and Close.
  • Agent change bar for changed files: who changed it, in which session, +/− counts, and Review (⌥⌘D, full diff). Added lines are tinted green with a + gutter mark; Diff also shows removed lines in red (read-only while shown).
  • Editing: line numbers, syntax colours from the terminal theme and font, ⌘S saves, edits survive redraws. Opens scrolled to the first agent change.
  • Status bar: language, indentation, encoding and line endings, and Saved / Edited state.
  • Built on CodeMirror 6; heavier work (search across files, refactors) stays in your own editor via Open in external editor.

Scope: three releases

The naming follows common practice. Alpha is the pilot MVP: the smallest working foundation, dogfooded by you. Beta is the minimum lovable product, which makes daily use fast and pleasant. The v1.x roadmap covers everything after that. Each release moves on only when its exit criteria are met.

Release 1 · Alpha

Pilot MVP

Goal: build it quickly, use it every day, and learn from it. Only the essentials. macOS on Apple Silicon only.

  1. Foundation. The Tauri 2 app talks to the lotsed daemon over a 0600 Unix socket. The daemon owns the PTYs, so sessions survive restarting the app.
  2. Add a project dialog (opened with "+" or ⇧⌘O). Projects persist across restarts and can be grouped into workspaces.
    • Browse folder: the native macOS folder picker. It takes a single project, a git repo, or a folder holding several repos, in which case Lotse offers to add each one.
    • Clone from URL: an HTTPS or SSH URL and a destination folder, cloned with your own git and credentials.
    • Create new project: a name and location, with an optional git init.
    • Or drag a folder from Finder onto the sidebar.
    After adding, the New Session sheet opens with that project selected.
  3. Run an agent session. Open a terminal tab in a project with Claude Code CLI, Codex CLI, OpenCode CLI or a plain shell. Uses xterm.js with WebGL.
  4. Sidebar. Workspace › Project › Agent › Sub-agent. Show or hide it (⌃⌘S), resize it from 200 to 420 px, and the width persists.
  5. Status detection.
    • Claude Code: hooks, covering sub-agents, PermissionRequest and StopFailure.
    • Codex: OSC 7501 plus a screen fallback.
    • OpenCode: a plugin.
  6. Status display. In progress, needs permission, failed, done, idle and unknown, each with a colour and a glyph. The most urgent state rolls up to collapsed projects and the workspace, and the Dock badge counts agents that need you. Session cards lead with a task title (from the first prompt, editable) rather than the agent name, and sub-agents fold into a summary line unless selected or blocked.
  7. Basic macOS notifications. One global on/off toggle per event: needs permission, failed, done.
  8. Appearance. Light, Dark or Auto. Interface font and terminal font each have their own family and size settings. ⌘+ / ⌘− change the terminal font size.
  9. Launch commands you can override in Settings › Agents (⌘,).
    • Terminal defaults to $SHELL -l, Claude Code to claude, Codex to codex, OpenCode to opencode.
    • You can add flags or a wrapper, and Reset puts the default back.
    • Settings shows the detected version or "not found on PATH".
    • The new-session sheet shows the command it will run.
  10. Project colour and icon, picked like in Apple Shortcuts.
    • 15 colour swatches and a searchable symbol grid, opened by clicking the project's icon.
    • Saved per project.
    • The default is a colour derived from the project name that avoids the status colours.
    • The real app renders SF Symbols through a native Swift helper (NSImage(systemSymbolName:)). Apple's license allows SF Symbols only in apps for Apple platforms, which this is, but check the terms before shipping exported SVGs. The mock uses Lucide as a stand-in.
  11. New session sheet (⌘T or the tab bar's "+"):
    • You pick project, then Terminal (the default), Claude Code, Codex or OpenCode.
    • An isolated git worktree is optional and off by default; the branch field appears only when you tick it.
    • The first-prompt field appears only for agents.
    • The sheet shows the command it will run.
  12. Git at a glance.
    • Session cards: a worktree or branch icon, the branch name, ↑ commits ahead and ± uncommitted changes.
    • Status bar: the same for the focused session, with a "worktree" tag.
    • Non-git folders: a crossed-out branch icon and "No git", in both the sidebar and the status bar.
  13. Project right-click menu: New Session, Notifications ›, Change Icon & Color, Reveal in Finder, Copy Path, Rename, Remove from Lotse.
  14. Session right-click menu: Open, Open in Split Right, Show Transcript, Show Changes, Stop Session.
  15. Status bar.
    • "▲ N need you", which filters the sidebar when clicked.
    • Git info for the focused session.
    • Daemon status and session count.
    • A bell to pause notifications.
    • LAN state.
    • Today's tokens and cost.
  16. Settings as a full page (⌘, or the gear next to the sidebar toggle).
    • Sections: Agents (launch commands), Notifications, Appearance (theme, interface font, terminal font), Remote, Privacy, Shortcuts.
    • The theme switch lives here, not in the main window.
  17. Speed basics. All of this is keyboard-first and kept out of sight until needed.
    • ⌘K jumps to any session or command.
    • ⌘J goes to the next session that needs you.
    • ⌘1–9 switch tabs, ⌘T opens the new session sheet, and ⌘/ lists the shortcuts.
    • Clicking "▲ N need you" filters the sidebar to only those sessions.
    • An unread dot marks sessions that finished in the background, and running sessions show a coarse elapsed time in minutes (seconds live in Usage & time).
    • Failed sessions swap their time for Retry on hover, in the same row.
    • A bell pauses notifications (⌥⌘N).
  18. Security baseline. Zero telemetry, no network ports, hook endpoints guarded by a token, hooks that can be uninstalled, keychain only for secrets.
Exit criteria:
  • You use it as your daily driver for 2 weeks, across 3 or more projects and all 3 agents.
  • Status matches reality at least 95% of the time.
  • No session is lost when the app restarts.
  • Feedback is logged as issues.
Release 2 · Beta

MLP: minimum lovable product

Goal: make the daily workflow effective and productive. Prioritise from the Alpha feedback.

  1. Approve or deny from a notification, using macOS alert-style notifications with Allow / Deny stacked on the right; "Always allow" sits in the notification's Options menu. You can also approve inline: the session card shows Allow / Always / Deny whenever it needs permission (no hover needed), or use the "need you" filter. This uses PermissionRequest returning decision.behavior; command hooks wait up to 600 s by default. It may need a Swift notification helper.
  2. Approve from the phone. A minimal LAN API that is off by default and bound to an interface you choose. Pair with a QR code and a pinned key. Each device gets a view or approve grant. The phone UI is a PWA showing the attention list.
  3. A git worktree per agent. The Changes panel shows:
    • a file count and the total +/−;
    • the branch, with a clickable PR pill;
    • uncommitted files with a status badge, +/− counts and a small change bar (clicking one opens the full diff for that file);
    • a "Review full diff" button;
    • the list of commits ahead of main.
    In full diff mode, clicking a file shows only that file, and "All files" shows everything. Each agent row shows branch, ahead/behind, dirty count, diff stat and PR status (read-only, via gh or glab).
  4. Side by side projects. Columns can be hidden, collapsed to a rail, or resized. Layouts are saved per display: a G9 49" fits 4 to 6 columns, a MacBook 1 to 2.
  5. Usage & time panel (⇧⌘U): session time (total, working, waiting on you), a sub-agent timeline on a time axis, tokens split into input / cache read / output, and spend today (session, project, all). Parsed from the transcript JSONL; history stored in SQLite.
  6. Files panel (⇧⌘F): the session's worktree tree, All / Changed toggle, filter (⌘P), +/− and status per changed file; clicking a file opens it in an editor pane beside the terminal.
  7. A light editor and diff. CodeMirror 6 with @codemirror/merge to edit, save and review agent changes. Files open as an editor split pane next to the agent terminal (same pane system, max 4), never replacing it; ⌥⌘↩ expands it to the full window. Full diff mode (⌥⌘D, or "Open full diff" in the Changes panel) is a full-window review: a changed-files list, a side-by-side or unified diff, and comments on individual lines. "Send review to agent" sends the comments as one prompt to that session. Copy patch is also available.
  8. A full notification matrix. Per-project overrides live under the project's right-click › Notifications: use global defaults, custom per event, or mute the project. A crossed-out bell or a dot marks the project in the sidebar. Per-project overrides, a sound per event, suppress when focused, and a 1.5 s quiet window.
  9. A command palette (⌘K), a keyboard shortcut for every action, and iTerm2-style splits with a status bar on each pane. You can open up to 4 sessions side by side from any project in four ways: ⌘D, ⌥-clicking a session, dragging a session card onto the terminal, or right-clicking › Open in Split Right. Dividers resize, ⌘[ and ⌘] move focus, and ⌘W closes a pane.
  10. A Settings › Agents pane showing hook and plugin install status and the detected CLI version.
  11. Session panel (⇧⌘I): every session in one place.
    • Header: agent, version, status, elapsed time and model.
    • Environment: machine, project, branch or worktree, and detection source.
    • Context: a usage bar that expands to show tokens, cache and cost.
    • Sub-agents with their durations, and background tasks with a Stop button.
    • Connectors (MCP): each agent's configured MCP servers with status (connected and tool count, needs sign-in, or failed with Retry). Read-only, with Manage opening the agent's own config: .mcp.json or ~/.claude.json for Claude Code, ~/.codex/config.toml for Codex, opencode.json for OpenCode. Live status comes from each CLI where it exposes it (unverified per CLI).
  12. Transcript view and export (⇧⌘T, right panel): a readable, searchable conversation (⌘F) with All / Messages / Tools / Approvals filters, tool calls grouped into compact cards, approvals marked, and a live "Working" bar with Latest ↓.
    • Sources:
      • Claude Code: the JSONL at the hook's transcript_path.
      • Codex: ~/.codex/sessions rollouts.
      • OpenCode: its local session store (unverified).
      • Any CLI: terminal scrollback.
    • Export to Markdown, JSON Lines or terminal text. Files are saved locally with secrets redacted.
  13. Voice dictation.
    • macOS Dictation types straight into the focused terminal. Use your own Dictation shortcut, set in System Settings › Keyboard › Dictation › Shortcut (the mic key or a modifier pressed twice). Do not hard-code a key.
    • A prompt composer (⌘⇧Return), a native-feeling text field that sends to the agent on Return, is the reliable fallback. It also gives multi-line editing.
      • System Dictation works in it as well.
      • Its mic button uses on-device Apple Speech (a small Swift plugin), so audio never leaves the Mac. A web view cannot start system Dictation from code.
      How the mic button works: the Tauri web UI calls a small native Swift plugin built on Apple's Speech framework, which turns speech into text on the Mac and streams it into the composer.
      Flow: click the mic, speak, watch the text appear live, edit it, then press Return to send to Claude Code, Codex or OpenCode.
      Privacy: recognition runs only on the device. It works offline and no audio leaves the Mac, in line with the zero-telemetry rule.
      Permissions: macOS asks once for Microphone and Speech Recognition access.
      Effort: about 2 to 4 days.
      Languages: English and German are expected on-device. Check against macOS 27 and 28 (unverified).
    • Spike early: whether xterm.js inside WKWebView accepts Dictation is unverified.
Exit criteria:
  • Median time from a permission prompt to your decision is under 30 s, including when you are away from the Mac.
  • You can review and merge agent work without leaving Lotse.
Release 3+ · v1.x

Roadmap (post-MVP)

Goal: breadth and polish, ordered by demand.

  1. A full mobile client: native iOS, or a complete PWA with terminal view and input. Multi-device management.
  2. A full editor: LSP, project search, multiple tabs, refactoring.
  3. An embedded browser for previewing what an agent built.
  4. Computer use, with per-action approval and an app allowlist.
  5. SSH remote hosts, by tunnelling the daemon socket.
  6. More agents through user-editable TOML detection manifests.
  7. A CLI and API for agent-to-agent orchestration (spawn, prompt, wait-until-blocked).
  8. Cost budgets and alerts, and history export.
  9. A menu-bar extra and widgets.
  10. Opt-in signed updates (Sparkle with EdDSA).
  11. A Linux build.
